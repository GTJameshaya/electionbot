# Бот для показаний счётчиков ⚡

Telegram-бот, который собирает показания электросчётчиков по двум домам — дальше будем звать их
**«дом 1»** и **«дом 2»** (настоящие названия задаются в локальном файле `houses.json`). Для каждого дома две ведомости: **жилые квартиры** и **«Коммерция»** (магазины и
прочие коммерческие абоненты). Вы пишете боту цифры прямо в чат, он раскладывает их по квартирам,
собирает Excel-ведомость по шаблону и отправляет её в рабочую группу. А для администраторов есть
веб-админка: зайти в неё можно одной кнопкой в боте, через Telegram, без логинов и паролей.

## 💬 Как это выглядит

Выбираете дом → «Жилые» → и просто пишете показания: номер квартиры и число, можно сразу несколько.

```
Вы:   12 345
Бот:  ✅ Сохранено 1 квартира

Вы:   2ц 100
Бот:  ✅ Сохранено 1 квартира

Вы:   ромашка 67 альфа 420
Бот:  ✅ Коммерция: ООО «Ромашка» — 67
      ✅ Коммерция: Альфа ЛТД — 420

Вы:   5ц 10
Бот:  ❌ Квартира 5ц не найдена. Может, 4ц (Цоколь 4) или 5?
```

_Названия абонентов здесь и ниже — условные, для примера._

Когда всё внесено — жмёте **«Готово»**, и ведомость улетает в группу. Пара полезных мелочей:

- Дробные числа — через точку или запятую: `30250,5`.
- Ошибка в одной паре не мешает остальным: бот сохранит правильные и перечислит, что не так.
- Если новое показание меньше прошлого месяца, бот предупредит (но всё равно сохранит).
- Повторный ввод той же квартиры в этом месяце просто перезапишет значение.
- **«Файл сейчас»** — прислать текущую ведомость себе, не отправляя в группу.
- Сессия хранится в базе, так что перезапуск бота ничего не теряет. Если отправка не удалась —
  просто нажмите «Готово» ещё раз.

### Цокольные квартиры

Квартиры с буквой «ц» (например, `2ц`, `3ц`, `4ц`) — это цоколь. Бот понимает их в любом написании: `2ц 345`,
`2 ц 345`, `ц2 345`, `цоколь 2 345`, `2c 345` (латиницей). В сообщениях они называются «Цоколь 2».
Ещё можно нажать кнопку «Нестандартные квартиры», выбрать нужную и отправить только число.

### Коммерция

Есть два способа:

- **Отдельная сессия «Коммерция»**: у каждого абонента своя кнопка (✅ — уже внесён в этом месяце).
  Нажали → бот показал прошлое показание → отправили число.
- **Прямо в жилой сессии**, вперемешку с квартирами: `12 345 ромашка 67 альфа 420 5ц 10`.
  Квартиры уйдут в жилую ведомость, абоненты — в коммерческую. По «Готово» бот отправит оба файла.

Абонента можно назвать полностью, началом названия, отличительным словом («аптека», «продукты»)
или псевдонимом («рома» → ООО «Ромашка»). Регистр, кавычки и опечатки с двойными буквами не важны.
Если подходит несколько абонентов (например, у одного магазина точки в двух подъездах), напишите
подъезд: `ромашка 1 67`, `ромашка1 67`, `ромашка 1п 67` — или бот сам спросит кнопками.

## 🚀 Быстрый старт

1. **Нужен Python 3.12.** На 3.13 python-telegram-bot 20.6 не запускается.
2. Окружение и зависимости:
   ```bash
   python3.12 -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   ```
3. Настройки: `cp .env.example .env` и заполните хотя бы `BOT_TOKEN`, `GROUP_CHAT_ID` и `ADMIN_USER_IDS`
   (все переменные — в таблице ниже).
4. **Список домов**: `cp houses.example.json houses.json` и впишите свои дома — название, хэштег,
   файлы шаблонов — и стартовые псевдонимы абонентов. Номер дома (`"1"`, `"2"`) — это его id в базе
   и `house1`/`house2` в именах файлов, у работающего бота его не меняйте.
   Без `houses.json` бот не запустится и подскажет, что делать.
5. **Положите Excel-шаблоны в корень проекта**: `template_1.xlsx`, `template_2.xlsx`,
   `template_1_commerce.xlsx`, `template_2_commerce.xlsx` (имена — как в `houses.json`).
6. Запуск:
   ```bash
   python bot.py
   ```

> ⚠️ Настоящих `houses.json` и шаблонов в публичном репозитории нет — в них адреса и данные жильцов.
> Возьмите их у администратора.

Если `BOT_TOKEN` или `GROUP_CHAT_ID` не заданы или заданы неверно, бот не запустится и напишет причину в лог.
Остановка по Ctrl+C / SIGTERM (systemd, `docker stop`) штатная, с кодом выхода 0.

## ⚙️ Переменные окружения (`.env`)

| Переменная | Нужна? | Что это |
|---|---|---|
| `BOT_TOKEN` | да | Токен бота от @BotFather. Нужен и админке — им проверяется вход через Telegram |
| `GROUP_CHAT_ID` | да | ID группы, куда уходят ведомости (у супергрупп начинается с `-100`) |
| `HOUSES_FILE` | нет | Путь к файлу со списком домов, по умолчанию `houses.json` в папке бота |
| `TARGET_BOT_TAG` | нет | Тег в начале подписи к файлу, по умолчанию `@supp0rt_dom` |
| `DATABASE_URL` | нет | База данных. По умолчанию `sqlite:///data/electionbot.db` (путь от папки бота). Для PostgreSQL: `postgresql+psycopg://…` и `pip install "psycopg[binary]"` |
| `ADMIN_USER_IDS` | да* | Telegram ID администраторов через запятую: бот + админка |
| `ALLOWED_USER_IDS` | нет | Telegram ID обычных пользователей: только бот |
| `ADMIN_PUBLIC_URL` | для админки | Внешний адрес админки, например `https://admin.example.org`. Для кнопки Mini App нужен `https://` |
| `ADMIN_SECRET_KEY` | для админки | Случайная строка от 32 символов для подписи cookie |
| `ADMIN_HOST` / `ADMIN_PORT` | нет | Где слушает админка, по умолчанию `127.0.0.1` / `8080` |
| `ADMIN_BOT_USERNAME` | нет | Username бота без `@` — включает Telegram Login Widget на странице `/login` |
| `CRM_INGEST_URL` | нет | Адрес приёма тикетов CRM (`…/api/ingest/ticket`). Вместе с токеном включает тикеты |
| `CRM_INGEST_TOKEN` | нет | Токен для CRM (уходит заголовком `Authorization: Bearer …`). Пусто — CRM выключена |

\* Если оба списка пусты и в базе ещё нет ролей, бот отказывает всем и пишет об этом в лог.
Свой Telegram ID человек увидит в ответе бота «нет доступа». Роли из `.env` применяются только к тем,
кого ещё не трогали в админке, — дальше роли меняются там.

## 📁 Что где лежит

| Файл | Зачем |
|---|---|
| `bot.py` | Сам бот: кнопки, сессии, ввод показаний, отправка в группу |
| `admin.py` | Веб-админка (FastAPI) |
| `admin_auth.py` | Проверка входа через Telegram (Mini App и Login Widget) |
| `config.py` | Чтение `.env` и `houses.json` |
| `db.py` | База данных: таблицы и все запросы |
| `parsing.py` | Разбор сообщений вида `12 345 2ц 100 ромашка 67` |
| `apartments.py` | Номера квартир: `2ц` / `цоколь 2`, подсказки «Может, 4ц?» |
| `ledgers.py` | Ведомости «Жилые» / «Коммерция» и поиск абонентов по названию и псевдонимам |
| `excel_report.py` | Чтение шаблонов и сборка Excel-ведомости |
| `migrate_archive.py` | Разовый перенос старого архива в базу |
| `captions.py` | Подпись к файлу и имя файла ведомости (общие для бота и админки) |
| `crm_ingest.py` | Тикеты в CRM: формат запроса, разбор ответа, понятные тексты ошибок |
| `logging_setup.py` | Общая настройка логов бота и админки (с вырезанием токенов) |
| `houses.json` | Дома, их шаблоны и стартовые псевдонимы абонентов (локальный, в публичный репозиторий не входит) |
| `houses.example.json` | Образец `houses.json` с вымышленными домами |
| `admin_templates/`, `admin_static/` | Страницы и стили админки |
| `template_*.xlsx` | Шаблоны ведомостей (в публичный репозиторий не входят) |
| `tests/` | Офлайн-тесты; `tests/fixtures/` — вымышленные дома и шаблоны для них |

Данные лежат в базе (по умолчанию `data/electionbot.db`). Excel собирается на лету из шаблона:
D — прошлый месяц, E — текущий, F — расход. Квартиры и абоненты берутся из шаблонов при запуске:
добавили строку в шаблон — после перезапуска она появится в боте.

## 🛠 Админ-панель

Отдельный процесс, работает с той же базой, что и бот:

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"   # → в .env как ADMIN_SECRET_KEY
python admin.py                                                # слушает 127.0.0.1:8080
```

**Как войти.** Логинов и паролей нет. Администратор жмёт в боте «🛠 Админ-панель» (или пишет `/admin`)
и получает кнопки:

- **«🛠 Открыть в Telegram»** — админка открывается прямо в Telegram как Mini App
  (только если `ADMIN_PUBLIC_URL` на `https://` с настоящим сертификатом);
- **«🌐 Открыть в браузере»** — одноразовая ссылка на 5 минут. Не пересылайте её никому.

По желанию можно включить Telegram Login Widget на `/login`: задайте `ADMIN_BOT_USERNAME`
и укажите домен админки в @BotFather через `/setdomain`. Роль проверяется на каждом запросе —
сняли роль, и доступ сразу закрыт.

**Что внутри:** сводка за месяц и кто ждёт доступа; правка показаний прямо в таблице (с журналом
«кто и когда»); «Кто не сдал»; квартиры и абоненты (добавить, отключить, переименовать с историей);
псевдонимы (бот подхватывает сразу); пользователи и роли; журнал отправок и скачивание Excel за любой
месяц; «Отправить в чат»; графики расхода. Последнего администратора понизить нельзя.

**Отправить в чат.** На странице «Отправить в чат» видны все дома и ведомости: текущий месяц и каждый
прошлый, за который в базе есть показания. Кнопка собирает Excel ровно так же, как бот, и шлёт его
в группу `GROUP_CHAT_ID` с обычной подписью. Режимы:

- **Просто сообщение** — подпись без тега `TARGET_BOT_TAG`, CRM не трогаем;
- **С тикетом** — подпись с тегом и тикет в CRM. Если по этой ведомости тикет уже был, по умолчанию
  файл дописывается в него («Дописать в тикет #N»), но можно выбрать «Новый тикет».

Перед отправкой — шаг подтверждения (дом, месяц, ведомость, режим, подпись). Подтверждение одноразовое:
двойной клик или повторная отправка формы второй файл не пошлют. Внизу страницы — журнал: кто, когда,
что отправил, номер сообщения в Telegram и итог в CRM (номер тикета, создан или дополнен, предупреждения
или понятный текст ошибки). Если `GROUP_CHAT_ID` не задан, кнопки выключены; если не настроена CRM —
выключен только режим «С тикетом».

- Отправка из админки — это настоящая доставка ведомости, поэтому она, как и отправка из бота, попадает
  в журнал «Отправки» (источник «админка») и ведомость за этот месяц считается отправленной.
- Если Telegram не ответил вовремя, статус будет «неизвестно» — файл мог дойти, загляните в чат.
  Тикет в CRM в этом случае не создаётся. Так же помечаются отправки, прерванные на полпути
  (например, админку перезапустили): через 10 минут «отправляется…» превращается в «неизвестно».
- Пользоваться страницей могут только администраторы — роль `admin` в базе. Первых администраторов
  берём из `ADMIN_USER_IDS`, дальше роли меняются на странице «Пользователи».

**CRM.** Когда заданы `CRM_INGEST_URL` и `CRM_INGEST_TOKEN`, бот после каждой удачной отправки ведомости
создаёт тикет в CRM (или дописывает в тикет этой же ведомости, если он уже есть; если CRM его не нашла —
создаёт новый). В тикет уходят подпись, файл, ID чата и сообщения, автор и метаданные (дом, месяц, вид
ведомости, источник, кто отправил). Ошибки CRM только пишутся в лог: файл в группу уходит в любом случае.
В боте запрос в CRM идёт фоном — ответ «✅ Файл улетел в группу» приходит сразу, не дожидаясь CRM.
Файл прикладывается, только если он меньше 20 000 000 байт (у CRM лимит 20 МБ); иначе тикет уходит
без файла с пометкой «файл не приложен: слишком большой». Формат запроса собран в одном месте —
`crm_ingest.build_request()`.

**Логи.** Токен бота и `CRM_INGEST_TOKEN` в логи не попадают: адреса запросов httpx не пишутся,
а все записи дополнительно проходят через фильтр, который вырезает токены (`logging_setup.py`).

**Безопасность.** По умолчанию админка слушает только `127.0.0.1`. Наружу её стоит выставлять
через nginx или Caddy с HTTPS, например:

```nginx
server {
    listen 443 ssl;
    server_name admin.example.org;
    ssl_certificate     /etc/letsencrypt/live/admin.example.org/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/admin.example.org/privkey.pem;
    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

Cookie подписана `ADMIN_SECRET_KEY` и живёт 12 часов, все формы защищены CSRF-токеном.

## 📦 Перенос старого архива

Если остались старые файлы `archive/YYYYMMDD_HHMM_house{N}_*.xlsx`, их можно один раз загрузить в базу:

```bash
python migrate_archive.py --dry-run   # сначала посмотреть, что будет загружено
python migrate_archive.py             # загрузить
```

- Месяц берётся из даты в ячейке D2 (если её нет — из имени файла); из нескольких файлов за месяц
  побеждает самый поздний.
- Что уже ввели через бота, не перезаписывается. Запускать повторно безопасно — ничего не задвоится.
- Коммерческие файлы (`…_house{N}_commerce_…`) попадают в «Коммерцию».
- Заодно из шаблонов подтягиваются записанные в них показания — только там, где в базе пусто
  (отключить: `--no-template`).

После переноса папку `archive/` можно оставить как резервную копию — бот её больше не читает.

## ✅ Тесты

Офлайн, без Telegram и сети (отправка в Telegram и CRM подменены). Настоящие `houses.json` и шаблоны тестам не нужны: они работают на вымышленных
домах из `tests/fixtures/` (шаблоны генерирует `python tests/fixtures/make_fixtures.py`).

```bash
python -m unittest discover -s tests
```
