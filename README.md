# Бот для сбора показаний счетчиков

Telegram-бот для сбора показаний счётчиков по двум домам: **Волкова д.9 к.1** и **Химиков 4**.

## Функционал

- Выбор дома («Волкова д.9 к.1» / «Химиков 4»)
- Ввод показаний сообщением вида `кв показание кв показание ...`, например `1 13100 2 30250,5 2ц 150`
  - дробные значения можно писать через `.` или `,`
  - ошибочные пары не отменяют остальные — бот сохранит корректные и перечислит ошибки
  - если новое показание меньше прошлого месяца — бот предупредит (значение всё равно сохраняется)
  - повторный ввод по той же квартире в этом месяце перезаписывает значение
- «Файл сейчас» — прислать текущую ведомость (xlsx)
- «Готово» — отправить ведомость в группу; сессия закрывается только после успешной отправки
  (если отправка не удалась — просто нажмите «Готово» ещё раз)
- Сессия хранится в БД и не теряется при перезапуске бота
- Доступ по ролям (администратор / пользователь / нет доступа), роли хранятся в БД
- Веб-админка (`python admin.py`): правка показаний, абоненты, псевдонимы, пользователи, отправки, графики, «Кто не сдал»

## Нестандартные квартиры (цоколь)

Квартиры, номер которых состоит не только из цифр, бот определяет автоматически по шаблону
(для любого дома). Сейчас это `2ц`, `3ц`, `4ц` в доме Волкова — «ц» означает **цоколь**.

- В сообщениях бота они показываются как «Цоколь 2», в Excel остаются исходные номера шаблона (`2ц`).
- При начале сессии бот показывает список таких квартир и пример ввода.
- Ввод понимает разные варианты: `2ц 345`, `2 ц 345`, `2-ц 345`, `ц2 345`, `цоколь 2 345`, `2 цоколь 345`,
  `2цоколь 345`, латиница `2c 345` / `2u 345` (вместо «ц»); похожие латинские буквы (a, e, o, p, c, x) заменяются на русские.
- Кнопка «Нестандартные квартиры» (только для домов, где они есть) — выбрать «Цоколь 2» и т.д.,
  затем отправить только число. Выбор хранится в БД и переживает перезапуск; «Назад» — отменить.
- Если квартира не найдена, бот подскажет похожие: `5ц` → «Может, 4ц (Цоколь 4) или 5?».

## Коммерция

У каждого дома, кроме жилой ведомости, есть ведомость коммерческих абонентов со своим шаблоном:
`template_1_commerce.xlsx` (Волкова) и `template_2_commerce.xlsx` (Химиков). Разметка коммерческого шаблона:
A1 — заголовок, A2 — дом, D2 — дата, A3 «Коммерческие подключения», строка 5 — месяцы (D — прошлый, E — текущий),
данные с 6-й строки: A — название абонента, D/E — показания, F — формула `=E-D` (бот её не трогает).
Лист с данными выбирается автоматически (первый непустой).

- После выбора дома бот спрашивает «Жилые» / «Коммерция».
- **Коммерция**: кнопка на каждого абонента (✅ — уже введён в этом месяце) + «Файл сейчас», «Готово», «Назад».
  Нажал абонента → бот показывает прошлое показание → отправляешь число. Можно и текстом: `озон 60500`, `щедрая 70000`.
- **Коммерция внутри жилой сессии**: можно писать вперемешку с квартирами — `12 345 лекс 67 пост 420 5ц 10`.
  Квартиры попадут в жилую ведомость, абоненты — в коммерческую (за тот же месяц). Бот подтвердит отдельно:
  «Коммерция: ООО «Борис» — 67».
- Если название подходит нескольким абонентам (в Химиков 4 «лекс» и «пост» — это 1 и 2 подъезд), укажи подъезд:
  `лекс 1 67`, `лекс1 67`, `лекс 1п 67`. Без подъезда бот ничего не сохранит и спросит кнопками, какой
  (вопрос хранится в БД и переживает перезапуск; «Назад» — пропустить).
- «Готово» в жилой сессии отправляет жилой файл, а затем — если в этом месяце вводилась коммерция,
  которая ещё не отправлялась, — коммерческий файл (отдельная подпись с «Коммерция» и `#Коммерция`).
- Имя коммерческого файла: `YYYYMMDD_HHMMSS_house{N}_commerce_<дом>.xlsx`.

### Псевдонимы

Абонента можно назвать полным названием, его началом или отличительным словом
(«овощной», «озон», «лавка»/«щедрая», «борис»). Дополнительные псевдонимы хранятся в БД (таблица `aliases`)
и редактируются в админ-панели (раздел «Псевдонимы») — бот подхватывает изменения сразу, без перезапуска.

При первом запуске таблица заполняется из `aliases.json` (файл остаётся как начальный набор и запасной
вариант, если БД недоступна; повторно он не перечитывается — дальше главнее админка):

```json
{"*": {"лекс": "борис", "пост": "пост лтд"}, "2": {"лавочка": "лавка"}}
```

`"*"` — для всех домов, `"1"`/`"2"` — для конкретного дома; значение — слово/фраза из названия абонента.
При сохранении псевдоним привязывается к найденным абонентам по их id (таблица `alias_targets`), поэтому
переименование абонента его не ломает; фраза дополнительно ищется по текущим **и прошлым** названиям.
Старые (только текстовые) псевдонимы привязываются автоматически при запуске.
Регистр, кавычки, точки и удвоенные буквы не важны («Леккс.» = «лекс»).

### Переименование абонента / смена владельца

Делается в админке («Квартиры и абоненты» → строка → «Переименовать»/«Смена владельца»): новое название и месяц,
с которого оно действует. Пишется история (`name_history`: было, стало, с какого месяца, кто и когда).
Показания остаются у той же строки, Excel за каждый месяц выводит название, действовавшее в том месяце
(коммерция — колонка A, квартиры — колонка B), бот узнаёт и старое, и новое название.
Если потом в шаблоне написать новое (или оставить старое) название — при запуске строка сопоставится
с существующей по истории названий, дубль не появится.

## Как хранятся данные

Показания хранятся в базе данных (SQLAlchemy 2.x). По умолчанию — SQLite-файл `data/electionbot.db`,
через `DATABASE_URL` можно переключиться на PostgreSQL.

| Таблица         | Что хранит |
|-----------------|------------|
| `houses`        | дома (1 — Волкова д.9 к.1, 2 — Химиков 4), хэштег, файл шаблона |
| `apartments`    | строки ведомостей: квартиры (`kind=residential`) и коммерческие абоненты (`kind=commerce`, название в `title`); заполняются из шаблонов при запуске |
| `readings`      | показание квартиры за месяц (`YYYY-MM`), кто ввёл, когда; одно значение на квартиру и месяц |
| `user_sessions` | активная сессия пользователя: дом, ведомость (жилые/коммерция), месяц, ожидаемый ввод |
| `submissions`   | журнал отправок ведомостей в группу (по дому, ведомости и месяцу), в т.ч. неудачных |
| `reading_audit` | журнал изменений показаний: было/стало, источник (бот/админка), кто, когда |
| `name_history`  | история переименований абонентов и смены владельцев квартир |
| `aliases`       | псевдонимы коммерческих абонентов (общие и по дому) |
| `bot_users`     | пользователи бота: user_id, username, первый/последний визит, роль |
| `login_tokens`  | одноразовые ссылки входа в админку (хранится только SHA-256 токена) |

Excel-файл формируется «на лету» из шаблона и БД:
колонка D — показания за **предыдущий календарный месяц**, E — за текущий, F — расход,
строка 4 — названия месяцев, D2 — дата. Шапка, сноски и прочие строки шаблона не изменяются.

Список квартир берётся из колонки A шаблона (начиная с 5-й строки). Если в шаблон добавили
квартиру — она появится в БД при следующем запуске бота. Строки, добавленные в админке,
дописываются в конец листа (оформление копируется с первой строки данных).

## Установка и запуск

```bash
pip install -r requirements.txt
cp .env.example .env      # заполнить BOT_TOKEN и GROUP_CHAT_ID
python migrate_archive.py # один раз, если есть старая папка archive/
python bot.py
```

Без корректных `BOT_TOKEN` и `GROUP_CHAT_ID` бот не запустится и напишет причину в лог.

Остановка по SIGTERM/SIGINT (systemd, docker stop, Ctrl+C) — штатная, с кодом выхода 0, даже если
последний запрос к Telegram при остановке не прошёл.

> Примечание: python-telegram-bot 20.6 не работает на Python 3.13 — используйте Python 3.10–3.12
> (или обновите библиотеку до 21.x).

### Переменные окружения (`.env`)

| Переменная         | Обязательна | Описание |
|--------------------|-------------|----------|
| `BOT_TOKEN`        | да  | токен от @BotFather |
| `GROUP_CHAT_ID`    | да  | ID группы для отправки ведомостей |
| `TARGET_BOT_TAG`   | нет | тег в подписи (по умолчанию `@supp0rt_dom`) |
| `DATABASE_URL`     | нет | по умолчанию `sqlite:///data/electionbot.db` (путь относительно папки бота) |
| `ADMIN_USER_IDS`   | да* | user_id администраторов через запятую (бот + админ-панель) |
| `ALLOWED_USER_IDS` | нет | user_id обычных пользователей бота через запятую |
| `ADMIN_PUBLIC_URL` | для админки | внешний адрес панели, например `https://admin.example.org` |
| `ADMIN_SECRET_KEY` | для админки | случайная строка ≥ 32 символов для подписи cookie |
| `ADMIN_HOST` / `ADMIN_PORT` | нет | где слушает панель, по умолчанию `127.0.0.1` / `8080` |
| `ADMIN_BOT_USERNAME` | нет | username бота без @ — включает Telegram Login Widget на странице входа |

\* Если `ADMIN_USER_IDS` и `ALLOWED_USER_IDS` пусты и в БД нет ролей — бот отказывает всем и пишет
в лог ошибку с подсказкой. Свой user_id человек увидит в ответе бота «нет доступа».

### Роли и доступ

- `admin` — бот + админ-панель (кнопка «🛠 Админ-панель» и команда `/admin`), `user` — только бот,
  `none` — нет доступа. Администраторы автоматически имеют доступ к боту.
- При запуске бота и панели роли из `.env` записываются в БД только тем, кого ещё не меняли вручную;
  после изменения роли в админке (раздел «Пользователи») главнее админка.
- Последнего администратора понизить нельзя.
- Каждый, кто пишет боту, попадает в `bot_users`; новые люди видны в админке как «Ожидают доступа»
  и получают доступ одной кнопкой «Разрешить».

## Админ-панель

Веб-интерфейс на FastAPI — отдельный процесс, работает с той же БД, что и бот.

```bash
pip install -r requirements.txt
# в .env: BOT_TOKEN, ADMIN_USER_IDS, ADMIN_SECRET_KEY, ADMIN_PUBLIC_URL
python -c "import secrets; print(secrets.token_urlsafe(48))"   # значение для ADMIN_SECRET_KEY
python admin.py                                                # слушает ADMIN_HOST:ADMIN_PORT (127.0.0.1:8080)
```

Разделы: **Главная** (сводка за месяц, ожидающие доступа), **Показания** (дом/ведомость/месяц: прошлое,
текущее, расход; правка и удаление прямо в таблице, отрицательный расход подсвечен красным, журнал «кто/когда»),
**Кто не сдал**, **Квартиры и абоненты** (добавить, отключить/включить, переименовать с историей),
**Псевдонимы**, **Пользователи** (роли, «Разрешить» одной кнопкой), **Отправки** (журнал + скачать Excel
за любой месяц — файл формируется из БД на лету), **Графики** (расход по месяцам по дому и по строке, SVG без
внешних библиотек). Вёрстка адаптирована под телефон.

### Вход — только через Telegram

Логинов и паролей нет. Администратор нажимает в боте «🛠 Админ-панель» (или `/admin`), бот присылает кнопки:

1. **«🛠 Открыть в Telegram»** — Mini App (если `ADMIN_PUBLIC_URL` начинается с `https://`). Панель проверяет
   подпись `initData` (HMAC-SHA256, ключ = HMAC("WebAppData", BOT_TOKEN)), свежесть (не старше суток) и роль.
   **Mini App работает только по HTTPS** с настоящим сертификатом.
2. **«🌐 Открыть в браузере»** — одноразовая ссылка `…/auth/tg?token=…`: случайный токен, в БД хранится только
   его SHA-256, действует 5 минут, срабатывает один раз и привязан к user_id. Ссылку нельзя пересылать.
3. Необязательно — **Telegram Login Widget** на странице `/login`: задайте `ADMIN_BOT_USERNAME` и в @BotFather
   `/setdomain` → домен панели. Подпись виджета проверяется (ключ = SHA256(BOT_TOKEN)).

Не-администраторы кнопку не видят, на `/admin` бот отвечает «Нет доступа»; панель проверяет роль на **каждом**
запросе — снятие роли сразу закрывает доступ.

### Безопасность

- Сессия — подписанная cookie (`ADMIN_SECRET_KEY`), `HttpOnly`, `SameSite=Lax`, `Secure` при https-адресе,
  срок 12 часов; кнопка «Выйти».
- Все изменяющие запросы (POST) защищены CSRF-токеном; вход Mini App подтверждается подписью Telegram.
- Заголовки: `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer` (токен не утечёт),
  встраивание во фрейм разрешено только Telegram (`frame-ancestors`), `Cache-Control: no-store`.
- По умолчанию панель слушает только `127.0.0.1`. Наружу публикуйте через nginx/Caddy с HTTPS, например:

```nginx
server {
    listen 443 ssl;
    server_name admin.example.org;
    ssl_certificate     /etc/letsencrypt/live/admin.example.org/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/admin.example.org/privkey.pem;
    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

- Единственные внешние скрипты — официальные `telegram.org/js/telegram-web-app.js` (страница входа Mini App)
  и `telegram-widget.js` (только если включён Login Widget). Остальное (CSS, графики) — локально.
- Правки показаний из панели пишутся в `reading_audit` с источником «админка» и `admin:<user_id>`.

## Перенос старого архива (`migrate_archive.py`)

Скрипт импортирует файлы `archive/YYYYMMDD_HHMM_house{N}_*.xlsx` (показания из колонки E) в БД:

```bash
python migrate_archive.py --dry-run   # посмотреть, что будет импортировано
python migrate_archive.py             # импорт
```

- месяц определяется по дате в ячейке D2 файла (если её нет — по дате в имени файла);
- если за месяц несколько файлов, берётся самый поздний;
- показания, уже введённые через бота, не перезаписываются;
- архивные коммерческие файлы (`..._house{N}_commerce_...xlsx`) импортируются в коммерческую ведомость;
- дополнительно из шаблонов (жилых и коммерческих) берутся записанные в них показания (как стартовые значения) —
  только там, где в БД пусто; отключить: `--no-template`;
- повторный запуск безопасен (ничего не дублируется).

После переноса папку `archive/` можно оставить как резервную копию — бот её больше не использует.
